# 技术方案：所有 Agent 单轮只询问一个问题

## 现状分析

根目录 `AGENTS.md` 已定义 Orchestrator、子智能体职责、委派规则和用户确认 Gate，但尚未规定面向用户提问时的数量、顺序和选项格式。该缺口会让不同 Agent 采用批量问答方式。

## 方案设计

在 `AGENTS.md` 的 Agent 协作规则附近增加独立的“单轮单问”小节，使用可直接执行的强制措辞，规定：

1. 规则适用主体为 Orchestrator 和全部子智能体。
2. 规则适用范围为所有面向用户的提问场景。
3. 每轮最多一个独立问题，不得用句式或排版规避。
4. 多个待确认项按阻塞程度排序，逐轮询问。
5. 单题可提供互斥选项，需标出推荐项及简短理由。
6. 子智能体需要用户输入时，只向 Orchestrator 上报一个当前最关键的问题。

不引入脚本、配置或新依赖。

## 接口与数据影响

- API：无
- 数据库：无
- 配置：无
- 外部依赖：无

## 兼容性与风险

- 兼容性：仅增加 Agent 行为约束，不改变仓库代码或 App 行为。
- 风险：过度拆分可能拉长访谈轮次；通过允许简短上下文、互斥选项和明确推荐降低沟通成本。
- 风险：Agent 可能把多个独立问题写成一个复合句；规则将明确禁止此类规避方式。

## 验证方案

1. 检查新增条款是否逐项覆盖需求文档中的七条业务规则。
2. 检查条款中是否只允许一个独立决策点，而非仅限制问号数量。
3. 检查 Git 改动范围是否仅包含需求记录、总清单和 `AGENTS.md`。
4. 由只读 Tester 独立对照验收标准检查最终改动。
