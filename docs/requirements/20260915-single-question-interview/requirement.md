# 需求方案：所有 Agent 单轮只询问一个问题

## 基本信息

- 需求编号：无
- 提出日期：2026-09-15
- 当前状态：已完成
- 关联人员：用户、Codex Orchestrator、所有子智能体

## 背景与问题

当前 `AGENTS.md` 没有明确限制 Agent 每轮向用户提出的问题数量，导致主会话或子智能体可能一次集中询问多个问题，增加回答负担，也破坏访谈式的逐步澄清体验。

## 需求目标

建立统一的单轮单问规则，使主会话和所有子智能体在任何需要向用户提问的场景中，每轮只提出一个问题，等待回答后再继续下一题。

## 需求范围

### 范围内

- 在根目录 `AGENTS.md` 增加用户提问规则。
- 规则覆盖主会话和所有子智能体。
- 规则覆盖需求访谈、澄清、确认、阻塞处理等所有向用户提问的场景。
- 允许单个问题附带互斥选项，但必须明确推荐项并简述理由。

### 范围外

- 不调整现有需求流程、确认 Gate、Agent 职责或状态流转。
- 不对 `AGENTS.md` 的其他重复、歧义或结构问题做整体重写。
- 不修改 `.codex/agents/` 中的角色定义。

## 业务规则

1. 主会话和所有子智能体每轮最多向用户提出一个问题。
2. 一个问题不得通过编号、并列分句或多个问号捆绑多个独立决策点。
3. 存在多个待确认项时，先询问当前最关键或最阻塞的一项，其余问题等待后续轮次。
4. 提问前可以提供必要的简短上下文。
5. 可以为单个问题提供互斥选项；提供选项时必须标出推荐项，并简述推荐理由。
6. 提问后必须等待用户回答，再提出下一问题。
7. 子智能体如需用户决策，应把一个最关键的问题交回 Orchestrator，由 Orchestrator 按相同规则询问用户。

## 验收标准

1. `AGENTS.md` 明确写出规则覆盖主会话和所有子智能体。
2. `AGENTS.md` 明确写出规则适用于所有向用户提问的场景。
3. `AGENTS.md` 明确禁止单轮提出多个独立问题或把多个问题包装成一个问题。
4. `AGENTS.md` 明确要求等待回答后再提出下一题。
5. `AGENTS.md` 允许互斥选项，并要求标注推荐项与简短理由。
6. 除需求文档、需求总清单和 `AGENTS.md` 外，无其他仓库文件发生变化。
