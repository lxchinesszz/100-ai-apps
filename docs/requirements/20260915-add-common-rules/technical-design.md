# 技术方案：新增通用开发规则

## 现状分析

`AGENTS.md` 已定义所有项目需要优先加载 `rules/common/`，但仓库当前只有 `rules/web-pwa/README.md`。因此公共规则层为空，跨平台共性的产品、代码、数据、测试和交付约束无法被统一加载。

`AGENTS.md` 的职责是仓库变更流程治理，不适合继续承载大量编码和产品细节；`rules/web-pwa/README.md` 又属于平台规则，不应该承担跨平台职责。

## 方案设计

新增单一入口：

```text
rules/common/
└── README.md
```

第一版采用单文件结构，保证 Agent 每次能完整加载公共规则。内容按以下八个主题组织：

```text
1. 产品原则
2. 技术原则
3. UI / UX 基线
4. 编码规范
5. 数据与状态
6. 测试与验证
7. 交付规范
8. AI Coding 约束
```

职责边界：

- `AGENTS.md`：负责需求归属、文档、确认、实施、验收、状态流转和规则加载。
- `rules/common/README.md`：负责所有平台共同遵守的开发质量基线。
- `rules/<platform>/README.md`：负责具体平台的技术、运行和部署细节。

规则强调“默认原则 + 禁止事项 + 验收要求”，避免写成泛泛建议。

## 接口与数据影响

- API：无
- 数据库：无
- 配置：无
- 外部依赖：无

## 兼容性与风险

- 公共规则不得覆盖具体平台合理差异；发生冲突时继续遵循 `AGENTS.md` 中的平台规则优先级。
- 不强制历史 App 立即重构；新需求和后续修改应逐步按公共规则执行。
- 第一版保持单 README，避免规则碎片化；后续内容明显膨胀时再拆分。

## 验证方案

1. 检查 `rules/common/README.md` 存在。
2. 检查八类主题完整覆盖。
3. 检查未复制 `AGENTS.md` 的 Mandatory Change Workflow。
4. 检查未出现 Web/PWA、小程序、桌面端特有技术细节。
5. 检查规则可以与现有 `rules/web-pwa/README.md` 叠加使用。
6. 检查没有修改任何具体 App。
