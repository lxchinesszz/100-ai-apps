# 需求方案：新增通用开发规则

## 基本信息

- 需求编号：无
- 提出日期：2026-09-15
- 当前状态：已确认
- 关联人员：用户、Agent

## 背景与问题

当前 `AGENTS.md` 已规定所有 App 开发前都需要加载 `rules/common/`，但仓库中目前仅存在 `rules/web-pwa/README.md`，缺少真正的跨平台公共开发规则。这样会导致产品原则、代码质量、数据处理、测试、交付等跨平台约束没有统一口径。

## 需求目标

新增 `rules/common/README.md`，建立适用于所有 App 的跨平台公共规则，覆盖产品、技术、UI / UX、编码、数据、测试、交付和 AI Coding 基本约束，同时避免重复 `AGENTS.md` 的需求流程，也不包含 Web / PWA、小程序、桌面端的专属规则。

## 需求范围

### 范围内

- 新增 `rules/common/README.md`。
- 定义产品与 MVP 原则。
- 定义技术复杂度控制和依赖原则。
- 定义通用 UI / UX 基线。
- 定义代码组织、命名、组件职责和抽象边界。
- 定义数据模型、持久化、版本升级和危险操作原则。
- 定义测试、构建、验收和边界场景要求。
- 定义 README、运行方式、构建方式、部署说明和已知限制等交付要求。
- 定义 AI 开发前后的基本检查顺序。

### 范围外

- 不重复 `AGENTS.md` 的需求创建、确认、实施、状态流转等流程。
- 不编写 Web / PWA 专属规则。
- 不编写微信小程序专属规则。
- 不编写桌面应用专属规则。
- 不修改任何具体 App。

## 业务规则

1. `rules/common/README.md` 只包含跨平台公共约束。
2. 通用规则必须强调 MVP First、简单优先、少依赖、避免无需求复杂化。
3. UI / UX 规则必须覆盖信息层级、核心操作、空状态、加载状态、错误状态和可发现性。
4. 编码规则必须强调职责清晰、减少重复、避免过度抽象和超大组件 / 文件。
5. 数据规则必须强调先定义模型、持久化可靠、版本升级和危险操作保护。
6. 测试规则必须要求 Build 通过、核心流程验证、异常与边界场景验证，不能只验证 Happy Path。
7. 交付规则必须让新的开发者或 Agent 能够理解如何运行、构建、部署和验证应用。
8. AI Coding 规则必须要求先读取需求、现有代码和规则，再实施、验证和回填结果。

## 验收标准

1. 仓库存在 `rules/common/README.md`。
2. 内容至少覆盖产品、技术、UI / UX、编码、数据、测试、交付、AI Coding 八个主题。
3. 不重复 `AGENTS.md` 的 Mandatory Change Workflow。
4. 不包含具体平台专属实现细节。
5. 能与 `rules/web-pwa/README.md` 叠加使用而不冲突。
6. 不修改任何具体 App。
