# 需求方案：锁定 Web / PWA App Shell 滚动

## 基本信息

- 需求编号：无
- 提出日期：2026-09-15
- 当前状态：已完成
- 关联人员：用户、Codex

## 背景与问题

现有 `rules/web-pwa/README.md` 已提出“App Shell 固定 + Content 独立滚动”，但根节点只使用 `min-height: 100dvh`，未明确限制 document 级滚动、滚动链和 iOS 边界回弹。开发者仍可能实现出整个页面像普通浏览器网页一样持续向下滚动、短内容页面可被拖动或回弹露底的效果。

## 需求目标

将 Web / PWA 明确约束为视口内运行的 App Shell：整个应用外壳不发生纵向页面滚动；内容超过可用空间时，只允许明确指定的内容区域内部滚动，从布局和手势反馈上消除普通网页感。

## 需求范围

### 范围内

- 明确根文档、应用挂载节点和 App Shell 的视口高度与 overflow 规则。
- 明确短内容、长内容、固定 Header / TabBar、滚动边界和 iOS 回弹的行为。
- 补充动态视口、Safe Area、横竖屏和软键盘场景的兼容要求。
- 补充允许整页滚动的例外条件与验收标准。

### 范围外

- 本次不逐个修改现有 App。
- 不禁止长内容在指定内容区内滚动。
- 不规定具体前端框架或引入新的滚动库。
- 不统一复杂手势、下拉刷新或虚拟列表方案。

## 业务规则

1. 默认禁止 `html`、`body`、`#root` 和 App Shell 形成 document 级纵向滚动。
2. App Shell 必须锁定在当前可用动态视口内，Header、TabBar 等外壳区域保持稳定。
3. 内容超过一屏时，只允许显式声明的主内容区或业务容器滚动。
4. 短内容页面上下拖动时不得移动整个 App、露出根背景或出现额外空白。
5. 内部滚动区到达首尾后，不应把滚动继续传递给外层 document。
6. Safe Area、浏览器地址栏变化、横竖屏和软键盘出现或收起时，关键内容和操作仍须可见、可达。
7. 文章阅读等确需整页自然滚动的页面可以例外，但必须在该 App 的需求和技术方案中明确记录理由与边界。

## 验收标准

1. 新规则明确区分“禁止整个 App 外壳滚动”和“允许指定内容区内部滚动”。
2. 新规则提供可直接采用的根节点、App Shell 和内部滚动区 CSS 基线。
3. 短内容页面不能产生 document 级纵向位移、回弹露底或多余滚动空间。
4. 长内容仅在指定区域滚动，Header 与 TabBar 不随内容移动。
5. 新规则覆盖滚动链、动态视口、Safe Area、横竖屏与软键盘兼容要求。
6. 新规则规定整页滚动例外必须由具体需求和技术方案显式批准。
7. Markdown 结构和代码块检查通过，且不破坏现有规则章节编号。

## 待确认事项

- 无。用户已确认按推荐边界执行：禁止整个 App 外壳上下滚动，但保留超长内容在中间指定区域内滚动。

## 实施结果

- 已在 Web / PWA 公共规则中锁定根文档、挂载节点和 App Shell 的 document 级滚动。
- 已提供 Flex 布局的固定外壳与内部滚动区 CSS 基线，并说明 Grid 的等效收缩约束。
- 已覆盖短内容、长内容、滚动链、iOS 系统手势边界、动态视口、Safe Area、横竖屏与软键盘场景。
- 已规定整页自然滚动只能作为具体 App 需求与技术方案显式批准的受控例外。
- 本次未修改任何现有 App，符合范围约束。
