# 技术方案：Web/PWA 公共部署脚本

## 现状分析

`rules/web-pwa/README.md` 已包含又拍云脚本实现和 `apps.springlearn.cn/<appSlug>/` 规则，但采用“复制到每个 App”的模式。`apps/001-trip/scripts/youpai-sync.js` 与 `apps/002-tripv2/scripts/youpai-sync.js` 是重复实现，且仍含旧服务标识，存在规则和实际脚本不一致的风险。

## 方案设计

新增 ESM 脚本 `scripts/youpai-sync.mjs`：

1. 接收两个位置参数：本地目录与远程目录。
2. 将本地目录解析为基于调用方当前工作目录的绝对路径。
3. 远程目录只接受 `/<kebab-case-appSlug>/`，明确拒绝 `/`、多层路径、点段和非法字符。
4. 固定又拍云服务 `100-ai-apps`，使用 `UPYUN_OPERATOR`、`UPYUN_PASSWORD` 完成 REST API 签名。
5. 递归读取本地文件，生成相对于本地目录的 POSIX 路径并逐个 `PUT` 到远程目录。
6. 根据扩展名设置常用 Content-Type；非成功状态立即终止并报告具体文件。
7. 不实现备份、GET 回读、哈希比较或 DELETE。

平台规则移除长篇可复制脚本，替换为公共脚本位置、参数契约、App 内 `deploy` 示例和安全边界，使文档以规则为主、实现保持单一来源。

## 接口与数据影响

- API：调用又拍云 REST API `v0.api.upyun.com` 的 PUT 上传接口
- 数据库：无
- 配置：需要 `UPYUN_OPERATOR`、`UPYUN_PASSWORD` 环境变量
- 外部依赖：又拍云；Node.js 内置模块，无新增 npm 包

## 兼容性与风险

- 公共脚本相对 App 工作目录解析 `localDir`，因此 App 内命令可稳定传入 `dist`。
- 各 App 必须显式传入远程目录，公共脚本不从项目目录自动推断，降低误判风险。
- 直接覆盖上传没有自动回滚能力；通过强制非根远程路径、凭证检查和失败即停止降低明显误操作风险。
- 不删除旧文件意味着历史哈希资源会保留，这是用户确认的安全边界。

## 验证方案

1. 对公共脚本执行 Node.js 语法检查。
2. 在临时目录中验证递归文件映射和参数校验。
3. 在无凭证环境验证脚本在联网前失败。
4. 静态检查脚本不存在 GET 回读、DELETE 和备份实现。
5. 对规则文档、公共脚本和两项 App 迁移执行独立 Tester 验收。
