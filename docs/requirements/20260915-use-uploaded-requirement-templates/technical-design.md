# 技术方案：使用用户提供的三份需求模板

## 现状分析

仓库已经存在 `docs/requirements/_template/requirement.md`、`technical-design.md`、`change-list.md`，但当前内容不是用户最终确认版本。本次不涉及代码逻辑，仅替换三个 Markdown 模板文件，并同步维护需求记录。

## 方案设计

直接使用用户上传的三份 Markdown 文件内容覆盖对应模板文件，不做字段增删、不做结构重排、不做措辞优化，确保后续所有新需求统一基于用户确认版本创建。

## 接口与数据影响

- API：无
- 数据库：无
- 配置：无
- 外部依赖：无

## 兼容性与风险

- 兼容性：文件名和目录保持不变，现有 `AGENTS.md` 对模板路径的引用继续有效。
- 风险：如果对用户模板做二次加工，可能偏离用户预期；因此本次采用原样替换。

## 验证方案

1. 替换后三个模板文件均可从 GitHub 正常读取。
2. 对照用户上传内容，确认标题、章节和占位内容一致。
3. 确认 `docs/requirements/README.md` 新增本需求记录并最终更新为 `Done`。
4. 确认本需求 `change-list.md` 已记录实际修改文件和验证结果。

## 方案确认

- 确认状态：已确认
- 确认记录：2026-09-15，用户明确要求“使用这三个模板”。
