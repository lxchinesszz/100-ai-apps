# 需求方案：又拍云凭证钥匙串兜底

## 基本信息

- 需求编号：无
- 提出日期：2026-09-16
- 当前状态：已完成
- 关联人员：用户、Codex Orchestrator、Developer、Tester

## 背景与问题

公共部署脚本 `scripts/youpai-sync.mjs` 当前只从环境变量读取又拍云操作员与密码。临时 `export` 仅在当前终端会话有效，导致用户每次重新打开终端后都要重复设置凭证。

## 需求目标

保留环境变量覆盖能力，并在 macOS 环境变量缺失时安全地从系统钥匙串读取凭证，使用户保存一次后即可直接运行部署命令。

## 需求范围

### 范围内

- `UPYUN_OPERATOR`、`UPYUN_PASSWORD` 环境变量保持最高优先级。
- macOS 上对缺失字段分别读取当前系统用户对应的钥匙串项目。
- 操作员 service 固定为 `100-ai-apps-upyun-operator`，密码 service 固定为 `100-ai-apps-upyun-password`。
- 使用参数数组调用 macOS `security` 命令，不经过 shell。
- 增加隔离测试，不访问真实钥匙串和又拍云。
- 同步 Web/PWA 平台规则中的凭证来源和安全边界。

### 范围外

- 不自动创建、更新或删除钥匙串项目。
- 不把凭证写入仓库、配置文件或日志。
- 不修改 App 的部署命令。
- 不执行真实部署。

## 业务规则

1. 每个凭证字段独立采用“环境变量优先、macOS 钥匙串兜底”的解析顺序。
2. 钥匙串查询 account 必须是 `os.userInfo().username`。
3. 非 macOS 且环境变量不完整时必须明确失败。
4. macOS 钥匙串项目缺失、为空或读取失败时必须明确失败，但错误信息不得包含任何凭证值。
5. 查询必须使用 `execFileSync` 和参数数组调用 `security find-generic-password`，不得启用 shell。

## 验收标准

1. 两个环境变量均存在时不访问钥匙串，并使用环境变量值。
2. macOS 上任一环境变量缺失时，仅为缺失字段读取对应 service，account 为当前用户名。
3. 非 macOS 环境变量不完整时给出可操作且不泄露凭证的错误。
4. macOS 钥匙串缺失或读取失败时给出可操作且不泄露凭证的错误。
5. 自动测试覆盖环境变量优先、单字段兜底、完整兜底、非 macOS 和钥匙串失败场景。
6. 现有部署参数、路径校验和上传行为保持兼容。
7. `rules/web-pwa/README.md` 不再声称凭证只能通过环境变量提供，并准确记录钥匙串 service、account、平台限制和保密要求。
