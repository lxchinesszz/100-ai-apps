# Web / PWA 验收清单

按当前需求的改动范围选择相关检查。模板初始化时验证一次框架基线；后续功能改动重点验证被修改的页面与流程。真实结果记录在当前需求的 `change-list.md`。

## 模板基线与构建

- [ ] 应用由 `create-pwa-app` 创建，或已记录不同的技术方案。
- [ ] `app.config.ts` 的元数据、slug 与实际应用一致，没有在页面或部署配置中重复写死。
- [ ] `pnpm lint` 和 `pnpm build` 通过。
- [ ] 首次建 App 或修改图标时，已替换模板图标并运行 `pnpm generate:pwa-assets`。
- [ ] PWA 安装、版本显示和手动更新能力未被业务改动破坏。

## 页面与交互

- [ ] 新增页面沿用 Konsta iOS Theme 和现有 App Shell。
- [ ] 新增长内容的滚动区域正确；无意外的 document 滚动。
- [ ] 新增固定底部区域无安全区域重复占位或 Home Indicator 遮挡。
- [ ] 输入法弹出时焦点、提示和提交操作可达。
- [ ] 核心触摸操作可发现，点击目标至少 `44 × 44px`。
- [ ] iPhone 常见宽度与主屏幕启动状态下，新增页面可用。

## 数据、路由与资源

- [ ] 承诺保存的数据在刷新和重新进入后保留，旧数据可读取。
- [ ] 功能的离线或断网表现符合当前需求；远程依赖有明确反馈。
- [ ] 新增路由可直接打开与刷新，资源在 `/<slug>/` 下正确加载。
- [ ] 图标语义一致，新增资源不会因路径或离线状态使核心操作失效。

## 发布时另行检查

- [ ] 用户已明确要求发布，应用内 `pnpm deploy` 的目标 slug 已核对。
- [ ] 实际 URL、Manifest、PWA 图标、路由和更新流程正常。
- [ ] 未上传凭证，远端目录中没有多余的 `dist/` 嵌套。

偏离模板基线或本目录规则的方案，应已在当前 App 的 `requirement.md` 和 `technical-design.md` 记录原因与影响。
