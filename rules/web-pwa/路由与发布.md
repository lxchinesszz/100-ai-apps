# 路由与发布边界

## slug 与子目录

新应用以 `app.config.ts` 的 `slug` 作为应用标识。模板据此配置 Vite base、Manifest `start_url` / `scope` 和应用内发布目录。不要在其他配置、页面或命令中重复写死 slug。发布并被添加到主屏幕后，slug 应视为稳定标识；变更须单独评估旧链接和安装入口。

## 新增路由

纯静态子目录部署时，新增多页面路由须确保直接打开和刷新不会产生 404。没有明确的 SPA fallback 时优先 Hash Router；如采用 Browser Router，应在当前需求与技术方案中记录服务器 fallback 配置及验证结果。

资源链接应适配 `/<slug>/` 子目录，不应无意识指向域名根路径。

## 发布

使用生成应用自己的 `pnpm deploy`。该命令根据 `app.config.ts` 推导部署目录，并会递增补丁版本、构建和上传；只有用户明确要求发布时执行。不要改用仓库根目录脚本，也不要为每个应用手写一份部署目标。

发布前按应用内 `NEW_APP.md` 运行所需的图标生成、`pnpm lint` 和 `pnpm build`，并核对目标 slug。上传 `dist/` 内的文件到 `/<slug>/`，不得额外嵌套一层 `dist/`。发布后检查实际访问地址、路由刷新、资源路径、Manifest 与 PWA 更新。

又拍云凭证不得进入源码、构建产物或日志。部署策略的变更需单独设计，不能因为清理旧文件而自行增加远端删除行为。
