# Konsta UI 业务界面规范

`create-pwa-app` 已集成 Konsta UI 并固定 iOS Theme。新增业务界面沿用这一基线。

## 组件选择

1. 标准 iOS 交互优先使用 Konsta 现有组件。
2. 使用 Konsta 组件与 Tailwind 组合完成布局和业务样式。
3. 只有标准组件无法满足明确业务需求时，才自定义 React 业务组件。

不要无理由引入第二套完整 UI 体系，也不要为 Konsta 已提供的 Navbar、Tabbar、List、Toggle、Segmented、Sheet、Dialog 等重新造一套通用组件。

## 页面交互

- 一级模块导航使用 Tabbar；页面内紧密相关的内容切换使用 Segmented。
- 列表型信息优先 List / ListItem，不默认把每项做成独立 Card。
- 创建、编辑、筛选与选择等短流程可优先考虑 Sheet；复杂流程使用 Popup 或独立页面。
- 确认和反馈使用应用组件，不把浏览器原生 `alert()` / `confirm()` 当作正式交互。
- 输入控件保持清晰的焦点反馈和 iOS 风格，避免额外叠加网页式蓝色 ring。不要移除焦点可见性而没有替代反馈。
- 核心触摸目标至少 `44 × 44px`，不能只靠悬浮或隐藏手势完成核心任务。
- 新增底部组件遵守 [应用布局与运行.md](./应用布局与运行.md) 的安全区域单次占位原则。

新增页面验收以信息层级、可发现性、触摸操作、输入法可用性和同一 App 内的一致性为准。
