# 旅记 · 产品需求文档

版本：v1.0 草案｜日期：2026-09-14

本文以已确认技术路线和[高保真效果图](../design/trip-high-fidelity.png)为依据。技术路线、四个核心界面和 Safari 添加到主屏幕的使用方式为已确认项；本文补充的计算口径、边界和备份功能为首版建议，供实现时统一执行。本地首版现已实现，实现与验证状态见[开发与部署](开发与部署.md)。

## 1. 产品定位

旅记是一款手机优先、离线可用的旅行预算记账工具。用户出发前设置整趟旅行的预算，途中快速记录花费，随时查看剩余预算及支出构成，结束后回顾旅行账单。

核心问题：这次旅行还能花多少钱，钱主要花在哪里？

首版服务个人维护的一本旅行账本。人数用于描述同行规模；所有金额都代表整趟旅行合计，不自动乘以人数，不代表人均，也不处理多人共同记账和 AA 结算。

## 2. 范围与优先级

| 优先级 | 功能 | 首版边界 |
| --- | --- | --- |
| P0 | 旅行列表 | 进行中、即将开始、历史旅行分组 |
| P0 | 创建与编辑旅行 | 目的地、起止日期、人数、人民币总预算 |
| P0 | 预算首页 | 剩余、已用、分类、每日流水 |
| P0 | 记账与纠错 | 新增、编辑、删除支出；食住行玩四类 |
| P0 | 本地持久化与 PWA | 无账号，添加到主屏幕，准备完成后离线使用 |
| P0 | 数据备份 | JSON 全量导出、恢复；防止本地账本无法迁移 |
| P1 | 今日建议与趋势 | 按第 5 节规则提供透明估算 |
| P1 | 分类详情 | 按分类筛选流水，查看合计 |
| 暂不纳入 | 云同步、登录、协作、AA、多币种 | 后续需单独设计数据和服务能力 |
| 暂不纳入 | 地图定位、攻略、预订、票据 OCR | 目的地手动输入，不调用定位服务 |

高保真中的照片采用内置封面或通用旅行封面，首版不承诺任意城市自动匹配图片。封面素材需取得使用许可并随应用缓存。

## 3. 使用路径与信息架构

首次：Safari 打开网站 → 查看添加指引 → 分享 → 添加到主屏幕 → 从旅记图标启动 → 创建旅行 → 记第一笔。

日常：主屏幕图标 → 旅行列表 → 进行中的旅行 → 记一笔 → 确认 → 预算与流水同步刷新。

列表是默认首页，不自动跳过存在多个旅行的选择。无旅行时展示简短介绍和“创建旅行”；不向真实账本写入演示数据。

Safari 网页和主屏幕应用不可假定共享账本。建议安装后再开始正式记账；若网页已有数据，提示先导出，再在主屏幕应用中恢复。安装引导可关闭，普通网页模式仍可使用。该设计依据 WebKit 对主屏幕应用存储隔离的说明，详见技术方案。

## 4. 页面与交互

### 4.1 我的旅行

保持效果图的白底、黑色大标题、蓝色添加按钮及旅行卡片。进行中卡片突出剩余预算、已花金额和预算进度；待出发卡片显示日期、人数和预算；历史卡片显示实际支出 / 预算。

按设备当前本地日期分组：开始日期之前为即将开始，起止日期内（含当天）为进行中，结束日期之后为历史。进行中按开始日期降序，待出发按开始日期升序，历史按结束日期降序，同值按创建时间降序。允许多个旅行日期重叠。

点击卡片进入详情；右上角加号创建；辅助菜单提供备份与恢复。无对应旅行时隐藏该分组；加载时显示轻量骨架；读取失败提供重试，不伪装为空账本。

### 4.2 创建 / 编辑旅行

| 字段 | 默认值 | 校验 |
| --- | --- | --- |
| 去哪儿 | 空 | 去除首尾空格后 1–40 个字符 |
| 出发 / 返回 | 今天 / 今天 | 有效日期，返回不早于出发；允许跨年及补记历史旅行 |
| 人数 | 1 | 整数 1–99，减号在 1 时禁用 |
| 旅行预算 | 空 | 0.01–9,999,999.99 元，最多两位小数 |

预算旁明确“整趟旅行总预算”。目的地旁图标为视觉标识，不呈现无法使用的定位按钮。日期控件必须能选择年份。

校验通过后可创建，保存期间禁用重复提交；只有本地保存成功才进入详情。失败时保留输入并给出重试入口。取消已有修改时提示放弃或继续编辑。

详情菜单允许编辑旅行及删除旅行。删除需明确告知将同时删除该旅行全部支出，并二次确认。调整日期后保留全部支出；日期范围外记录标记“行程外”，仍计入总花费。

### 4.3 旅行预算首页

布局依次为返回与菜单、目的地和日期人数、剩余预算大数字、已使用进度、今日建议、分类汇总、每日流水、底部“记一笔”。底部按钮不得遮挡最后一条记录。

支出分类固定为食、住、行、玩，展示金额及占总支出比例。无支出时四类均为零。流水按消费日期降序分组，同日按消费时间降序，再按创建时间和 ID 排序；显示每天合计。备注为空时使用分类名称。点击流水进入编辑。

未开始旅行显示“距出发 N 天”，历史显示“旅行已结束”，两者不显示“今日建议”。历史仍可补记和修改。超支时主数字改为“已超支 ¥X”，进度条满格并用文字说明，不仅依靠颜色。

### 4.4 记一笔

采用底部弹层：标题与关闭、金额、四分类、可选备注、确认按钮、数字键盘。默认“食”；新记录默认设备当前本地日期时间，展开辅助项可修改消费日期时间以补记。历史旅行打开时默认结束日及当前时刻，并允许调整。

金额从空值开始；允许整数或最多两位小数，范围同预算，禁止负数、零和科学计数。按“.”得到“0.”，重复小数点无效；删除键逐位删除。备注最多 100 字。

数字键盘由应用内成熟 React 组件提供，金额区不同时唤起系统数字键盘；编辑备注时使用系统键盘并隐藏自定义键盘。键盘收起后恢复布局。键盘按钮和分类按钮至少 44×44 CSS 像素。

确认按钮随输入显示金额；成功写入后关闭弹层并更新页面，重复点击不产生重复记录。失败保留金额、分类和备注。未保存内容关闭时需确认；页面切后台不主动丢弃表单，但首版不承诺杀进程后恢复未提交内容。

### 4.5 备份与恢复

辅助入口提供“导出全部数据”和“从备份恢复”。导出包含所有旅行与支出，不包含应用缓存。文件内含格式版本与导出时间。

恢复前先校验文件、展示旅行及支出数量，并明确“替换此设备当前账本”。建议先导出当前数据；用户确认后在一个事务中替换。无效文件、未知版本、写入失败不得破坏现有账本。首版不实现合并，以免生成重复记录。

## 5. 金额、日期与预算口径

所有计算使用整数分，显示采用人民币；整数金额可省略小数，非整数保留两位小数。天数按日历日期计算，包含出发日与返回日，不按相差小时数除以 24。

设预算 B，总支出 S，行程天数 N，当前第 d 天，今日支出 T，今日之前的全部支出 P。行程外支出也计入 S；P 包含出发前支出。

| 指标 | 规则 |
| --- | --- |
| 剩余预算 R | B − S；允许负数 |
| 已用比例 | S / B，显示四舍五入整数百分比；条形宽度限制 0–100%，文字可超过 100% |
| 分类占比 | 分类金额 / S；S=0 时为 0%；各项独立取整，不强制相加为 100% |
| 剩余旅行天数 D | 结束日期 − 今天 + 1，仅进行中计算 |
| 今日建议可用 A | floor(max(0, R + T) / D) − T，再限制最低为 0；单位为分 |
| 预测总支出 F | P + (P / (d−1)) × D，仅 d≥2 时计算，最终取整到分 |
| 预测结余 | B − F；负数显示“预计超支” |

今日建议将扣除所有已记录非今日支出后的预算平均分配给今天及剩余日，再扣除今天已经花费的部分。未来日期的已记录支出也视为已占用预算，避免重复分配。

预测仅在至少完整经过一个旅行日、且不存在未来日期支出、且无出发前/结束后支出时启用，否则显示“记录不足，暂不预测”或“包含行程外支出，暂不预测”。预测文案明确“按已完成旅行日的日均支出估算”，不把它当作保证。

状态优先级：R<0 为“已超支”；R=0 为“预算已用完”；其余有预测时，F>B 为“注意预算”，F≤B 为“预算充足”；无预测时为“持续记录中”。

**效果图数据校正：**图中 B=2,000，S=702，R=1,298，分类 186+288+200+28=702；当天三笔 28+20+80=128。如果这是第 1/3 天，A=(1298+128)/3−128≈347.33 元，而非图中 486 元。图中“预计剩余 286”也缺少可推导依据。实现采用上述统一规则，486 和 286 仅视为视觉占位；正式演示数据须保证每日流水与总额一致。

## 6. 视觉与体验要求

基础交互优先复用成熟 React 移动端组件，统一定制为苹果风格；不要求自行实现弹层、日期选择、数字键盘等通用能力。

参照效果图的轻量 iOS 风格：白色背景、细灰分隔线、蓝色主要操作、浅灰表单、绿色预算提示，大金额使用等宽数字。顶部状态栏、灵动岛和底部系统手势条由系统呈现，网页不绘制模拟手机外壳。

以 375–430 CSS 像素手机宽度为主要目标，兼顾 320 像素窄屏和横屏。使用系统中文字体、安全区域留白、可滚动内容和稳定底部操作。桌面显示居中窄版，不另做复杂后台布局。支持文字放大、明确焦点、按钮可读标签和减少动态效果设置。

“10 秒创建”和“3 秒记账”为可用性目标，指熟悉流程且输入简单时，不作系统耗时保证。

## 7. 离线与数据说明

首次访问和首次安装后应联网打开应用，等待“已可离线使用”。此后断网仍能查看、创建、编辑及删除旅行和支出。缓存尚未就绪时不声称离线可用。

数据保存在当前设备、当前应用环境；无账号、无自动云同步。清理网站数据、系统回收或设备损坏可能造成丢失，备份入口以短说明解释这一点。应用升级不得主动清空账本。

## 8. 验收清单

1. 四个主界面的布局、层级和交互与高保真方向一致，无模拟系统状态栏。
2. 创建、刷新、关闭并重开后旅行与支出仍在；离线状态完成同样操作。
3. 日期跨年、单日旅行、多个进行中旅行均正确分组，跨午夜后重新计算。
4. 支出 0.10+0.20 精确为 0.30；编辑和删除同时刷新余额、分类和每日合计。
5. 保存连续点击只有一条记录；保存失败不关闭输入；数据库错误不显示假成功。
6. B=2000、S=702 时剩余为 1298；超支、零余额、无支出均有明确状态。
7. 备份导出后恢复内容等价；损坏文件和失败恢复保持原账本完整。
8. Safari 添加到主屏幕后独立启动；实机验证安装前后数据环境并可通过备份迁移。
9. 应用更新提示不打断正在记账；更新和数据库升级后记录保留。
10. iPhone 系统键盘、底部弹层、安全区域和长流水列表不遮挡主要操作。

## 9. 交付顺序

第一阶段完成四页与核心 CRUD；第二阶段完成预算规则、纠错和备份；第三阶段完成 PWA、实机离线及更新验证；最后部署又拍云并验收正式域名。预测属于 P1，不能阻塞核心记账上线。
