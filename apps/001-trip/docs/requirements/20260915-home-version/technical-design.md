# 技术方案：首页显示版本号

## 现状分析

应用版本当前记录在 `package.json`，首页品牌入口位于 `src/features/trips/TripList.tsx` 的 `.wordmark`。Vite 配置尚未向客户端注入版本或构建时间，页面也没有版本标识。

## 方案设计

将版本升至 `0.1.1`。`vite.config.ts` 读取 `package.json` 版本，并通过 Vite `define` 注入 `import.meta.env.VITE_APP_VERSION` 与 `import.meta.env.VITE_BUILD_ID`。生产构建启动时按 `Asia/Shanghai` 生成一次 `YYYYMMDD-HHmm CST` 标识；开发命令固定使用 `DEV`。首页直接渲染两个注入值，并用现有品牌排版补充低强调度样式。

## 接口与数据影响

- API：无
- 数据库：无
- 配置：新增两个 Vite 编译期常量
- 外部依赖：无

## 兼容性与风险

- 构建时间在构建启动时固定，客户端刷新不会改变。
- 版本号直接来源于 package，避免重复手工维护。
- 不触碰 iOS meta、manifest 和全屏 CSS，避免影响已验收能力。

## 验证方案

1. 自动化测试检查首页展示入口与 Vite 注入配置。
2. 执行类型检查和生产构建。
3. 检查构建产物包含 `v0.1.1` 与明确的 `CST` 构建标识。
4. 运行全屏回归测试，确认原配置未回退。

## 实施结果

- 应用版本已升至 `0.1.1`，`package-lock.json` 已同步；pnpm 锁格式不记录根项目版本，依赖图无需变化且与当前声明一致。
- Vite 已注入 package version 与构建启动时生成的上海时间标识，JSON import 使用 import attribute，兼容 Vite 后续原生配置加载器。
- 首页“旅记”旁已增加低强调度版本标识，未改变首页操作与信息结构。
- 已新增 3 项版本回归测试；连同全屏测试共 7 项全部通过。
- 当前构建产物固定包含 `0.1.1` 与 `20260915-2215 CST`，供部署直接使用。

## 方案确认

- 确认状态：已确认
